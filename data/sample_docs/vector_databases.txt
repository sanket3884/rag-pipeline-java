A vector database, or vector store, is a system specialized for storing high-dimensional numeric vectors and efficiently finding the vectors most similar to a given query vector, typically using cosine similarity, dot product, or Euclidean distance as the similarity measure.

The simplest possible approach is brute-force search: compare the query vector against every stored vector and sort by similarity. This is exact and simple to implement, but its cost grows linearly with the number of stored vectors, which becomes impractical beyond roughly tens of thousands of vectors depending on hardware.

To scale beyond brute force, most production vector stores use approximate nearest neighbor, or ANN, algorithms. One widely used ANN algorithm is HNSW, or Hierarchical Navigable Small World graphs, which builds a multi-layer graph structure where each vector is a node, allowing searches to quickly navigate toward the nearest neighbors without checking every vector. HNSW trades a small amount of recall, meaning it might occasionally miss the true nearest neighbor, in exchange for dramatically faster search times, often sub-linear in the number of vectors.

Popular vector database options include dedicated systems like Milvus, Qdrant, and Weaviate, which run as standalone services and offer features like metadata filtering, multi-tenancy, and horizontal scaling. Alternatively, vector search capability has been added directly to existing databases and search engines: Postgres has the pgvector extension, Elasticsearch and OpenSearch use Lucene's HNSW implementation under the hood, and Redis has a vector similarity module. Choosing between an embedded library-based approach and a standalone service typically comes down to operational complexity versus scaling and feature needs.
